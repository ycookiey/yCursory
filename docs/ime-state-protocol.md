# IME状態の受信（プロトコルv1）

IMEや外部ツールは、IMEのオン・オフとキャレットの位置をyCursoryに送信できる。

送信側が入力を担当すると通知したウィンドウを、担当ウィンドウと呼ぶ。

- 担当ウィンドウが前面にあり、オン・オフを受信している間は、yCursoryは前面のアプリにIME状態を問い合わせず、受信したメッセージだけでカーソルの色を変更する。
- yCursoryがキャレットの位置を取得できないアプリでも、メッセージがあれば色が追従する。
- 担当ウィンドウが前面にない間と、担当開始からオン・オフを最初に受信するまでの間は、yCursoryが前面のアプリに問い合わせる。
- 送信側がいなければ、yCursoryは常に前面のアプリに問い合わせる。

## 送信先

- yCursoryは受信用に、クラス名が`yCursory.ImeStateReceiver.v1`のメッセージ専用ウィンドウを作成する。`FindWindowExW(HWND_MESSAGE, NULL, L"yCursory.ImeStateReceiver.v1", NULL)`で検索し、`PostMessageW`で送信する。送信側がyCursoryの処理を待たないよう、`SendMessage`は使用しない。
- yCursoryが起動していない間は、受信用のウィンドウは存在しない。
- メッセージ番号は、`RegisterWindowMessageW`に次の名前を渡して取得する。

| 名前 | wParam | lParam | 意味 |
|---|---|---|---|
| `yCursory.ImeState.v1.Focus` | ウィンドウのHWND | 1: 担当開始 / 0: 担当終了 | 指定したウィンドウの担当を開始または終了する。詳細は下の「Focusの動作」 |
| `yCursory.ImeState.v1.Open` | 1: オン / 0: オフ | 0 | 担当ウィンドウのIMEのオン・オフ。オンは日本語入力 |
| `yCursory.ImeState.v1.Caret` | `MAKELONG(left, top)` | `MAKELONG(right, bottom)` | キャレットの位置。変換中の文字列の位置でもよい。物理ピクセルで、各値は16ビット符号付き。wParamとlParamがどちらも`0x80008000`なら、位置なし |

HWNDと各値は32ビットに収まるため、64ビットと32ビットのどちらのプロセスからも送信できる。

### Focusの動作

HWNDには、担当するウィンドウの子ウィンドウを指定してもよい。yCursoryは`GetAncestor(hwnd, GA_ROOT)`で取得した最上位のウィンドウ（以下、root）で比較する。

- 担当開始（lParamが1）: 指定したウィンドウのrootを担当ウィンドウに設定する。別のウィンドウを担当していた場合は置き換える。担当開始より前に`Open`で受信したオン・オフは、同じウィンドウへの担当開始でも破棄する。
- 担当開始で、HWNDが0または存在しないウィンドウの場合: 担当を開始せず、現在の担当ウィンドウがあれば担当を終了する。
- 担当終了（lParamが0）で、HWNDのrootが担当ウィンドウと一致する場合: 担当を終了する。
- 担当終了で、HWNDが0の場合: どのウィンドウを担当していても担当を終了する。
- 担当終了で、HWNDのrootが担当ウィンドウと異なる場合: 何もしない。

### OpenとCaretの動作

- `Open`は、担当ウィンドウがない間は破棄する。担当ウィンドウが前面にあるときだけ、カーソルの色とキャレットインジケーターの色に反映する。
- `Caret`は、担当ウィンドウが前面にあるときだけ使用する。yCursoryは`left`と`top`のみを使用し、`right`と`bottom`は使用しない。

## 送信側の規則

- 担当開始の送信直後に、現在のオン・オフを`Open`で送信する。yCursoryは担当開始の時点で、担当開始より前に受信したオン・オフを破棄し、`Open`を受信するまで前面のアプリに問い合わせる。
- 変換が終わったら、位置なしの`Caret`を送信する。送信しないと、最後の位置にキャレットインジケーターが残る。
- `Caret`は、位置が変化するたびに送信する必要はない。最後の1件だけを送信すればよい。
- 担当を終了するときは、担当終了を送信する。
- 担当ウィンドウが前面でなくなると、yCursoryは担当を終了する。担当ウィンドウが再び前面になったら、担当開始と`Open`を送信し直す。

## yCursoryがメッセージを使用する条件

- メッセージを使用するのは、前面のウィンドウのrootが担当ウィンドウと一致する間だけ。
- OSから前面のウィンドウの切り替えの通知を受けた時点で、前面のウィンドウのrootが担当ウィンドウと異なれば、担当を終了する。通知は遅延することがあるため、切り替え先として通知されたウィンドウではなく、通知を受けた時点の前面のウィンドウで比較する。担当ウィンドウが閉じられたことを検知した時点でも、担当を終了する。
- 担当の終了後は、送信側が再び担当開始を送信するまで、yCursoryが前面のアプリに問い合わせる。
- yCursoryは16msごとに、前面のアプリからIME状態とキャレットの位置を取得する。キャレットの位置を1秒続けて取得できないと、yCursoryは前面のアプリからの取得を停止し、前面のウィンドウかフォーカスが切り替わると再開する。SetWinEventHookの登録に失敗した場合は停止しない。
- `Caret`の位置を使用するのは、前面のアプリからの取得が停止している間だけ。取得している間は、キャレットインジケーターに取得した位置を使用する。キャレットインジケーターが無効の場合は、`Caret`の位置を使用しない。
- 受信用のウィンドウは、すべてのプロセスからのメッセージを受け付ける。サンドボックス内のアプリのIMEなど、権限の低いプロセスからも受信できるよう、`ChangeWindowMessageFilterEx`で許可している。偽のメッセージで変化するのは、カーソルの色とキャレットインジケーターの表示だけ。
