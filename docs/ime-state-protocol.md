# IME状態の受信（プロトコルv1）

IMEや外部ツール（以下、送信側）はIMEのオン・オフとキャレットの位置をyCursoryに送信できる。

送信側が入力を担当すると`Focus`で通知したウィンドウを、担当ウィンドウと呼ぶ。

- 担当ウィンドウが前面にあり、担当開始の後にオン・オフを受信していれば、yCursoryは前面のアプリにIME状態を問い合わせず、受信したオン・オフでカーソルの色を決める。
- yCursoryがキャレットの位置を取得できないアプリでも、そのアプリのウィンドウが担当ウィンドウなら、`Open`を受信した時点でカーソルの色が変わる。
- 担当ウィンドウがない間と、担当開始からオン・オフを最初に受信するまでの間は、yCursoryが前面のアプリに問い合わせる。問い合わせを停止する条件は[yCursoryがメッセージを使用する条件](#ycursoryがメッセージを使用する条件)を参照。

## 送信先

- yCursoryは受信用に、クラス名が`yCursory.ImeStateReceiver.v1`のメッセージ専用ウィンドウを作成する。送信側は`FindWindowExW(HWND_MESSAGE, NULL, L"yCursory.ImeStateReceiver.v1", NULL)`で受信用のウィンドウを検索し、`PostMessageW`で送信する。送信側がyCursoryの処理を待たないよう、`SendMessage`は使用しない。
- yCursoryが起動していない間は、受信用のウィンドウは存在しない。
- メッセージ番号は`RegisterWindowMessageW`に次の名前を渡して取得する。

| 名前 | wParam | lParam | 意味 |
|---|---|---|---|
| `yCursory.ImeState.v1.Focus` | ウィンドウのHWND | 1: 担当開始 / 0: 担当終了 | 指定したウィンドウの担当の開始・終了。詳細は[Focusの動作](#focusの動作)を参照 |
| `yCursory.ImeState.v1.Open` | 1: オン / 0: オフ | 0 | 担当ウィンドウのIMEのオン・オフ。オンは日本語入力 |
| `yCursory.ImeState.v1.Caret` | `MAKELONG(left, top)` | `MAKELONG(right, bottom)` | キャレットの位置のスクリーン座標。変換中の文字列の位置も送信できる。単位は物理ピクセル。各値は符号付き16ビット。wParamとlParamがどちらも`0x80008000`なら、位置がないことを示す（以下、位置なし） |

HWNDと各値は32ビットに収まるため、64ビットと32ビットのどちらのプロセスからも送信できる。

### Focusの動作

HWNDには担当するウィンドウの子ウィンドウも指定できる。yCursoryは、指定されたウィンドウを`GetAncestor(hwnd, GA_ROOT)`で取得した最上位のウィンドウ（以下、root）に置き換えてから、担当ウィンドウや前面のウィンドウと比較する。

- 担当開始（lParamが1）: 担当ウィンドウを、指定したウィンドウのrootにする。別のウィンドウを担当していた場合は置き換える。担当開始より前に`Open`で受信したオン・オフは、担当開始の対象が同じウィンドウでも破棄する。
- 担当開始で、HWNDが0か、存在しないウィンドウを指す場合: 担当を開始せず、現在の担当ウィンドウがあれば担当を終了する。
- 担当終了（lParamが0）で、HWNDのrootが担当ウィンドウと一致する場合: 担当を終了する。
- 担当終了で、HWNDが0の場合: どのウィンドウを担当していても担当を終了する。
- 担当終了で、HWNDのrootが担当ウィンドウと異なる場合: 何もしない。

### OpenとCaretの動作

- `Open`は、担当ウィンドウがない間は破棄する。担当ウィンドウが前面にあるときだけ、カーソルの色と、キャレットの位置に表示するグロー（以下、キャレットインジケーター）の色に反映する。
- `Caret`の位置は、担当ウィンドウが前面にあり、yCursoryが前面のアプリへの問い合わせを停止していて、キャレットインジケーターが有効なときだけ、キャレットインジケーターの表示位置に使用する。使用するのは`left`と`top`だけ。

## 送信側の規則

- 担当開始の送信直後に、現在のオン・オフを`Open`で送信する。yCursoryは担当開始の時点で、担当開始より前に受信したオン・オフを破棄し、`Open`を受信するまで前面のアプリに問い合わせる。
- 変換が終わったら、位置なしの`Caret`を送信する。送信しないと、最後の位置にキャレットインジケーターが残る。
- `Caret`は、位置が変化するたびに送信しなくてよい。位置が続けて変化したときは、最後の位置だけを送信すればよい。
- 担当を終了するときは、担当終了を送信する。
- 担当ウィンドウが前面でなくなると、yCursoryは担当を終了する。元の担当ウィンドウが再び前面になったら、送信側は担当開始と`Open`を送信し直す。

## yCursoryがメッセージを使用する条件

- `Open`と`Caret`を使用するのは、前面のウィンドウのrootが担当ウィンドウと一致する間だけ。
- 前面のウィンドウが切り替わったとOSから通知を受けた時点で、前面のウィンドウのrootが担当ウィンドウと異なれば、担当を終了する。通知は遅延することがあるため、切り替え先として通知されたウィンドウではなく、通知を受けた時点の前面のウィンドウで比較する。担当ウィンドウが閉じられたことを検知した時点でも、担当を終了する。
- 担当の終了後は、送信側が再び担当開始を送信するまで、yCursoryが前面のアプリに問い合わせる。
- yCursoryは16msごとに、前面のアプリにIME状態とキャレットの位置を問い合わせる。キャレットインジケーターが無効の場合、キャレットの位置を問い合わせるのは、再開の後にキャレットが見つかるまでの間だけ。キャレットの位置を1秒続けて取得できないと、yCursoryは問い合わせを停止し、前面のウィンドウかフォーカスが切り替わると再開する。前面のウィンドウとフォーカスの切り替えの通知を`SetWinEventHook`で登録できなかった場合は、再開できなくなるため、問い合わせを停止しない。
- `Caret`の位置を使用するのは、前面のアプリへの問い合わせを停止している間だけ。問い合わせている間は、キャレットインジケーターに、問い合わせで取得した位置を使用する。キャレットインジケーターが無効の場合は、`Caret`の位置を使用しない。
- 受信用のウィンドウは送信元のプロセスを確かめずに、3種類のメッセージを受け付ける。サンドボックス内のアプリのIMEなど、権限の低いプロセスからも受信できるよう、`ChangeWindowMessageFilterEx`で3種類のメッセージを許可している。送信側を装ったプロセスが誤った状態を送信しても、変化するのはカーソルの色とキャレットインジケーターの表示だけ。
